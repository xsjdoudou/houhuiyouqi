# 后会友期人格测试

微信小程序：16 道题，每题 4 个选项，匹配一位可能成为好朋友的嘉宾并展示理由，支持云端记录、删除记录和分享结果。嘉宾画像和匹配是主观趣味设定，非官方测评，不代表嘉宾真实性格、实际交友意愿或心理诊断。

## 虚拟支付状态

**尚未完成，不可用于收费，也不要部署当前开发版本。** `cloudfunctions/payment` 的下单入口硬编码关闭；新版记录接口与旧版小程序不兼容，且需要订单集合，单独部署 `records` 会影响现有用户。不要修改开关或配置生产支付，直到以下事项全部完成并经过真实环境验证：

- [x] 本地开发版的结果计算和文案在服务端，记录读取按用户及已发货订单授权；这尚未部署和验证数据库权限。
- [ ] 本地已实现服务端查单和发货通知处理，但还没有完成微信云开发的推送绑定、端到端验证和定时兜底。通知会再次查单，不信任客户端可伪造的事件。
- [ ] 本地已接入手动刷新支付状态和下单前的权益、未完成订单检查，以及按用户唯一锁防止并发下单；该锁尚未在云数据库验证。退款人工核对和权益回收流程尚未验证，不能开启收费。
- [ ] 根据后台已发布的真实道具 ID 和价格核对 `payment-config.js`；当前 `one_time`、`always` 是代码中的标识，不能假定与后台一致。
- [ ] 云数据库集合仅允许云函数访问，完成部署及小额真单、重复推送和退款等验证。

`payment` 是事件云函数，准备就绪前不需要部署；届时选择合适的 Node.js 运行时，并由管理员在云函数环境变量中配置 `WECHAT_APPID`、`WECHAT_APP_SECRET` 和 `VIRTUAL_PAYMENT_APP_KEY`。密钥不要写进代码、提交 Git 或发送给他人。调用方身份由云开发提供，登录 code 仅用于在服务端换取支付签名所需的 session key。

发货通知目前只处理 `xpay_goods_deliver_notify`，即使事件来自客户端也会先查微信订单，非可信退款事件不会撤销权益；其他事件返回失败，不能当作退款已处理。查单状态 `2` 才会尝试发货，查单失败不会解锁。启用前必须验证发货通知格式、数据库索引和权限，并建立可执行的退款人工核对和权益回收流程。

支付代码还需要 `payment_order_locks` 集合，必须禁止客户端读写。锁依赖云数据库对指定文档 `_id` 的唯一性，部署前需确认云端 SDK 的行为；如果订单写入结果不确定，锁会保留，不能直接删除，需要先核对微信订单和本地订单。收货完成或订单关闭后可以清理相应终态锁。

### 退款人工处理

当前不提供小程序内主动退款入口，也不实现自动退款通知处理或自动回收权限。这不代表平台退款被关闭，平台退款及用户权利以微信、Apple 的实际规则和适用要求为准；面向用户的退款说明须在上线前核对，不能一概宣称不允许退款。

上线前需指定负责人和定期核对频率，在微信后台虚拟支付交易订单中检查各支付渠道的退款状态。发现退款时，先核实平台最终退款结果、支付订单及用户身份，并记录处理依据；不能仅凭退款申请或接口受理结果撤权。

业务拟定规则为：确认退款成功后，人工回收该用户当时已有的全部结果解锁权益，包括永久和其他单次权益；实施前须核对平台规则和适用要求，并区分退款后新购买的权益。当前没有管理后台或已验证的人工回收工具，不能认为仅修改本文档就能完成操作。必须先在隔离环境验证操作、并发和审计流程，保护其他用户及新购买权益，再考虑启用收费。

开发版的分享只指向首页，不携带结果类型、用户身份、原始答案或记录 ID；旧版结果分享链接在新版不再展示结果。当前不保存原始答案，历史列表最多显示最近 100 条。旧版客户端曾包含完整结果和算法，无法通过更新撤回已下载的旧代码；上线前需要评估旧客户端兼容性和访问风险。

上线前请根据实际数据处理方式配置隐私保护指引，核对类目、审核、云服务费用及节目和嘉宾相关的名称、肖像等使用授权。题目和结果文案是原创示例；修改题目时需同步客户端题目与 `cloudfunctions/records/content.js`，修改计分规则或结果文案只应修改服务端，并按兼容方案部署。
